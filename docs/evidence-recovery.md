# 상호작용 근거 복구 및 생성형 답변 제거

확인일: 2026-09-11

## 원인

운영 사이트와 연결된 Supabase 프로젝트를 대조한 결과, 식품 277,074건과 영양제 4,380건은 있었지만 `public.drug_food_interactions` 테이블은 없었습니다. Data API의 `PGRST205` 오류와 PostgreSQL의 `to_regclass` 결과로 확인했습니다. 삭제·미생성 시점이나 실행 주체는 이번 조사에서 확인되지 않았습니다.

기존 조회 코드는 DB의 `error`를 검사하지 않고 빈 배열로 처리했습니다. 생성형 분석은 근거가 없어도 일반 의학 지식으로 답변하도록 되어 있었고, 답변 문구에 따라 안전 등급을 부여했습니다. 다른 조합의 DB 자료가 하나라도 있으면 AI 출처를 DB 출처로 바꾸는 후처리도 있었습니다. 이 구현은 검색 근거만 사용하는 방식이 아니었습니다.

먼저 운영 결과 생성 API를 HTTP 503으로 중단한 뒤, 사용자 승인에 따라 원본을 검증·복구하고 원문 조회 방식으로 전환했습니다.

## 복구한 원본

- 로컬 보관본: `Drug to Food interactions Dataset.json`, `drug_food_interactions.csv`
- JSON의 약품 1,423개에서 추출한 원문 2,512건과 CSV의 약품명·원문이 순서까지 일치함
- 중복 약품명·원문 조합: 0건
- 원본 JSON SHA-256: `8078106b88873f4e8c8b6656cf933a933d9fc29b6c8bf3427f6b81ec3ee9b17c`
- 정렬된 레코드 MD5 식별자 목록의 대조값: `5dea7ed3abb405015fc47089d58fb846`
- 복구 후 원문에서 다시 계산한 대조값도 일치하며, 저장된 식별자와 내용이 다른 행은 0건
- 보관본의 문헌: Knox et al., DrugBank 6.0, Nucleic Acids Research 2024, DOI `10.1093/nar/gkad976`

원문에 없는 내용을 보충하거나 LLM으로 재작성하지 않았습니다. 위 문헌 표기는 보관본에 포함된 메타데이터이며, 개별 조합의 임상적 타당성을 새로 검증했다는 뜻은 아닙니다.

## 저장·권한

`restore_drug_food_evidence_table` 마이그레이션으로 원문 테이블을 복구했습니다. RLS를 활성화하고 `anon`과 `authenticated` 역할에는 SELECT만 부여했습니다. 공개 참조 데이터이므로 Data API를 통한 읽기는 가능하며, 일반 클라이언트의 INSERT·UPDATE·DELETE 권한은 없습니다. 개인 계정이나 복약 기록은 이 테이블에 넣지 않았습니다. 데이터 원본 파일은 GitHub에 올리지 않습니다.

추가 필드는 원문별 식별자, 보관본 출처 문헌, 원본 SHA-256입니다. 파일 해시는 복구 무결성·버전 식별용이며 의학적 신뢰도 점수가 아닙니다.

## 현재 조회 규칙

1. 요청의 약품·음식만 사용하며, 클라이언트가 제공한 근거·출처·성분·판정은 신뢰하지 않습니다.
2. 승인된 데이터셋 해시와 2,512건의 존재를 확인합니다. 오류·불완전한 데이터셋은 503으로 중단합니다.
3. 정확한 약품명 또는 제품명 일치가 확인된 식약처 성분명으로 조회합니다. 공식 검색 결과 최대 100건에서 일치 후보들을 검토하며, 성분이 충돌하거나 비어 있거나 전체 결과가 확인되지 않으면 임의로 선택하지 않습니다.
4. 음식 이름과 명시적인 번역 별칭으로 원문을 검색합니다. 음식에서 영양소를 추정하거나 일반적인 식사 안내를 개별 음식의 근거로 바꾸지 않습니다.
5. 원문 있음·근거 부족을 표시합니다. 모든 조합에 결과 항목을 만들되 LLM 호출, 안전 판정, 임의 설명 생성, 출처 자동 승격은 하지 않습니다.
6. 기록에 남은 과거 생성형 결과는 재확인 대상으로 표시하며 의학적 근거처럼 다시 표시하지 않습니다.

이는 벡터 검색이나 생성형 RAG가 아니라 제한된 키워드 기반 원문 검색입니다. 영어 원문은 그대로 표시합니다. 제품 식별·음식 별칭·데이터 범위의 한계로 누락될 수 있으며, 검색어 일치가 곧 특정 조합에 대한 검증은 아닙니다.

## 검증과 한계

- 자동 테스트: 37개. 근거 없는 조합, 다른 약·음식 근거 섞임, 위조 출처, DB 오류·부분 복구, 잘못된 요청, LLM 미호출, 과거 생성형 응답 차단, 공식 제품 후보 선택·성분 충돌·검색 잘림 포함
- 로컬 브라우저: 320/1440px의 원문 있음·근거 부족·혼합 결과와 오류·재시도 등 9개 시나리오
- 실제 DB 연결: 타이레놀·알로시아와 커피·우유는 근거 부족, 타이레놀·알코올과 Warfarin·자몽은 보관본 원문 반환. 이는 검색 동작 확인이며 해당 조합의 안전성 평가가 아님
- 기존 iOS CORS 프리플라이트 유지. 물리 iPhone 재빌드·실제 OAuth 전 과정은 별도 확인 필요
- 데이터 최신성·임상적 정확도·원저작물 사용권·서비스의 법적 적합성은 이번 무결성 검사만으로 입증되지 않음

검색 구현은 Supabase의 [대소문자 구분 없는 필터](https://supabase.com/docs/reference/javascript/using-filters-ilike)와 [조회 제한 시간](https://supabase.com/docs/reference/javascript/using-modifiers-abortsignal)을 사용합니다. DB 오류가 빈 결과로 처리되지 않도록 분리합니다.

## 복구 직후 발견한 검색·색상 회귀

2026-09-11 후속 점검에서 타이레놀·알코올이 0건으로 표시되는 문제를 확인했습니다. 식약처 검색을 한 건만 요청해 첫 번째인 어린이 제품을 가져왔고, 엄격한 제품명 검증이 이를 제외하면서 두 번째의 일반 타이레놀 제품은 확인하지 않았습니다. 데이터 자체는 Supabase에 존재했습니다. 검색 결과에서 제품명이 맞는 후보들을 확인하도록 수정했고, 첫 결과가 다른 제품인 경우를 서버 회귀 테스트에 추가했습니다.

생성형 판정을 제거하면서 결과 화면까지 회색으로 바꾼 것은 필요 이상의 디자인 변경이었습니다. 근거 부족·재확인은 기존 주황색 계열로 복구하고 원문 있음은 파란색으로 구분합니다. 조회 상태만 표현하며 근거 없는 초록색 안전 판정이나 왼쪽 세로 장식선은 다시 추가하지 않습니다.
