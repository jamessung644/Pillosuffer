# 뭐무꼬 / PilloSuffer v1

현재 운영 웹 앱의 소스입니다. [운영 사이트](https://pillosuffer-v1.vercel.app)

2026-09-11 기준 상호작용 조회는 LLM을 사용하지 않는 원문 검색 전용입니다. 기존 입력·로그인 복귀·오류 처리 수정과 홈 버튼 네 가지 색상은 유지하며, 결과 카드의 왼쪽 세로 장식선은 제거했습니다.

## 실행

Node.js 22와 npm을 기준으로 확인했습니다. 이 폴더에서 실행합니다.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

`.env.local`에 본인 프로젝트의 환경변수 값을 설정해야 합니다. 개발 주소는 `http://localhost:3001`입니다.

```bash
npm test
npm run build
npm start
```

단위 회귀 테스트는 외부 API 호출 없이 실행됩니다. `npm start` 기본 주소는 `http://localhost:3000`입니다. 브라우저 회귀용 `tests/browser.cjs`·`tests/result-browser.cjs`는 별도 Playwright 실행 환경이 필요하며, 결과 화면 테스트는 가상 인증·API 응답을 사용하는 로컬 테스트입니다.

## 환경변수

| 이름 | 사용 위치 | 용도 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | 브라우저·서버 | Supabase 프로젝트 주소 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 브라우저·서버 | 공개 클라이언트 키. service role 키를 넣지 않습니다. |
| `GEMINI_API_KEY` | 서버 | 음식 이미지 인식에만 사용. 상호작용 조회에는 사용하지 않음 |
| `GOOGLE_VISION_API_KEY` | 서버 | 웹 약봉투 OCR |
| `MFDS_API_KEY` | 서버 | 식약처 e약은요·의약품 제품 허가정보 조회 |
| `NEXT_PUBLIC_API_BASE` | 브라우저 | 웹에서는 비움. 네이티브 앱은 API 운영 주소 사용 |

실제 키, `.env.local`, Vercel 인증 정보와 데이터베이스 원본은 저장소에 포함하지 않습니다.

Supabase에서는 Google 로그인을 별도로 설정하고 로그인 반환 주소 `/auth/callback`을 로컬·배포 도메인에 맞춰 등록해야 합니다. 검색은 `processed_foods`, `supplements`, `drug_food_interactions` 테이블에 의존합니다. 해당 데이터와 데이터 이용 권한은 별도 준비가 필요하며, 이 저장소만 설치한다고 기존 운영 데이터까지 생성되는 것은 아닙니다. 공개 키의 데이터 접근 범위는 해당 프로젝트의 RLS 정책으로 제한해야 합니다.

## 구조

- `app/`: 홈, 촬영·직접 입력, 약 확인, 음식 입력, 결과, 약 관리, 프로필·로그인 화면
- `app/api/`: OCR, 음식 이미지, 약품 데이터, 상호작용 분석 API
- `components/`: 약 카드, 단계 표시, 내비게이션, 결과·출처 표시
- `lib/`: 모델 호출, 외부 데이터 조회, 기기 저장, 응답 검증
- `tests/`: 저장 데이터·오류 응답 단위 테스트와 브라우저 회귀 테스트
- `plugins/vision-ocr/`: 운영 웹 의존성에 필요한 로컬 패키지 메타데이터

현재 `main`의 이 폴더는 웹 배포 기준입니다. 네이티브 iOS 프로젝트 전체는 이 폴더에 포함하지 않았으며, 기존 `ios-app` 브랜치를 이번 공개 작업으로 변경하지 않았습니다.

## 원문 조회·저장 방식

- 상호작용 API: `app/api/safety-check/route.ts` → `lib/retrieve-evidence.ts` → `lib/evidence.ts`. 클라이언트가 보내는 근거·출처·성분 추측은 무시하고 서버에서 DB를 조회합니다.
- `drug_food_interactions`에는 `id`, `drug_name`, `interaction_description`, `source`, `source_reference`, `dataset_sha256`가 필요합니다. 현재 승인된 보관본의 SHA-256과 전체 2,512건이 확인되지 않으면 HTTP 503으로 중단합니다. 빈 테이블을 만드는 것만으로는 실행되지 않습니다.
- `lib/evidence.ts`의 음식 이름 번역 별칭과 정확한 약품명·공식 성분명으로 검색합니다. 음식 이름에서 영양소를 추정하거나 약품명만 일치하는 일반 안내를 특정 음식의 근거로 사용하지 않습니다. 복합 제품명·별칭 누락으로 검색되지 않을 수 있습니다.
- 식약처 제품허가 검색은 첫 결과를 그대로 사용하지 않고 제품명이 일치하는 후보들을 확인합니다. 후보의 성분이 서로 다르거나, 성분이 비어 있거나, 전체 결과를 확인할 수 없는 경우(100건 초과 포함) 성분을 임의로 선택하지 않습니다. 이때는 더 정확한 제품명이 필요할 수 있습니다.
- 결과의 `mode`는 `retrieval-only-v1`, 각 항목의 `evidenceStatus`는 `found` 또는 `missing`입니다. `references`에 실제 원문·출처·레코드 ID·데이터셋 해시를 제공합니다. `found`는 검색어 일치이지 의학적 판단이 아닙니다.
- 기존 클라이언트 호환용 `verdict: caution`은 유지하지만 의료 위험 등급이 아닙니다. 새 웹 화면은 이 값으로 색상이나 등급을 만들지 않습니다. 이전 생성형 결과 기록에는 `재확인 필요`만 표시합니다.
- 결과 화면은 원문에 명시된 회피 지침에 기존 빨강(rose), 함께 복용하도록 명시된 지침에 초록(emerald), 확인 필요에 주황(amber)을 사용합니다. 큰 한국어 행동 안내·이유를 먼저 보여주고 영어 원문·출처·식별자는 펼쳐보기로 제공합니다. 왼쪽 세로 장식선은 사용하지 않고 홈 버튼 색상은 유지합니다.
- `lib/evidence.ts`의 `SOURCE_INSTRUCTIONS`는 실제 DB에서 확인한 5개 원문 전체 문장에 대한 고정 번역 규칙입니다. 이 문구와 음식 검색어가 정확히 일치할 때만 `guidance`를 제공합니다. 현재 규칙은 술·자몽 회피와 물 한 컵을 동반한 복용 지침이며, 원문 일부의 단어나 AI 해석으로 범위를 넓히지 않습니다. 코드의 문구 대조이지 약사·의사의 임상 검토 완료를 뜻하지 않습니다.
- 초록색은 확인된 모든 성분(`ingredientNames`)과 해당 조합의 모든 조회 원문에 명시적인 허용 지침이 있는 경우에만 표시합니다. 현재 허용 규칙은 물 복용 지침으로 제한하며, 일반적인 식사 가능 문장을 커피·우유의 허용 근거로 사용하지 않습니다. 추가 조건·미등록 문구·부분 근거·검색 실패는 초록색이 되지 않습니다. 초록색도 개인의 질환·용량·다른 약까지 포함한 무조건적인 안전 보증은 아닙니다.
- `lib/safety-llm.ts` 및 AI 대체 응답·출처 자동 승격 로직은 삭제했습니다. 모델은 `lib/gemini.ts`에서 음식 이미지 인식에만 사용하며 기존 Gemini 3.8 Flash 설정은 유지합니다.
- 약 정보·프로필·검사 기록: 현재 기기 저장소 사용. 계정 간·기기 간 자동 동기화는 구현하지 않음
- 결과 화면: 로그인 필요

데이터셋 복구 경위와 공개 읽기 권한은 [복구 기록](../docs/evidence-recovery.md)을 참고하세요. 데이터 원본은 GitHub나 Vercel 소스에 포함하지 않습니다.

## 배포

GitHub 연동으로 새 Vercel 프로젝트를 만들 때 Root Directory는 `Pillosuffer_v1`로 지정합니다. 기존 운영 프로젝트에는 이미 환경변수와 도메인 연결이 있으므로 별도 확인 없이 새 프로젝트로 교체하지 않습니다.

운영 프로젝트에 연결된 이 폴더에서 수동 배포할 때는 다음과 같습니다.

```bash
vercel link
vercel --prod
```

## 검증 범위

입력·오류 처리·근거 격리·위조 출처 차단·DB 오류 중단·LLM 미호출·공식 제품 선택·원문 행동 지침 등 자동 테스트 45개를 통과했습니다. 별도 로컬 브라우저 테스트는 320/1440px의 회피·허용·확인 필요·혼합 결과, 원문 펼쳐보기·색상·오류·재시도 등 13개 시나리오를 확인합니다. 결과 화면의 인증은 가상 응답으로 검사하므로 실제 Google 로그인 검증은 아닙니다.

실제 Google 로그인 완료, 물리 iPhone 동작, 데이터 최신성·임상적 정확도·사용권 검토는 별도 확인이 필요합니다. 원문 보관본의 복구·전송 무결성 검사는 의학적 검증이 아닙니다. 발표 자료의 과거 평가 수치는 현재 검색 정확도나 안전성 보장이 아닙니다.

이 서비스는 참고 정보 제공용이며 진단·처방이나 약사·의사의 판단을 대체하지 않습니다.
