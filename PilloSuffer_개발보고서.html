1프로젝트 개요

복용 중인 약과 음식·영양제의 상호작용 위험을 촬영 한 번으로 확인하는 모바일 웹 서비스

📷 약봉투 인식

Google Vision OCR로 약봉투를 인식하고 개인정보(이름·주민번호·병원명)를 자동 마스킹

🔬 성분 기반 분석

약품명 → 공식 영문 성분으로 변환 후 DrugBank·식약처 데이터와 교차 검색

🤖 AI 안전 판정

검색된 근거를 바탕으로 Gemini가 safe / caution / danger 3단계 위험도와 근거를 생성

두 가지 버전

v1 — Light

밝은 테마(포트 3001). 의약품 정보 패널(ℹ️), 약 필터 등 기능 검증용 메인 버전

v2 — Dark

다크 대시보드 테마(포트 3002). 동일 기능을 세련된 UI로 재구성

3RAG 파이프라인

검색(Retrieval) → 증강(Augment) → 생성(Generate) → 후처리(Guardrails)

STAGE 0 · 입력 수집
약봉투 OCR(Google Vision) + 음식 텍스트/사진 인식(Gemini Vision) → PII 마스킹
▼
STAGE 1 · 검색 (Retrieval) · /api/mfds
정적 매핑에 없는 약은 제품허가 API로 영문 성분 해석 → DrugBank 교차검색 + e약은요 병렬 조회
1a 성분해석약품명→Digoxin
+
1b 음식키워드바나나→potassium
→
1c DrugBank교차 검색
∥
1d e약은요병용금기
▼
STAGE 2 · 증강 (Augmentation)
e약은요 ★최우선 → DrugBank 보조 → 환각방지·의료법 회피 규칙을 프롬프트로 조립
▼
STAGE 3 · 생성 (Generation)
Gemini가 약×음식 조합별 verdict + 근거 + 출처를 JSON으로 생성
▼
STAGE 4 · 후처리 (Guardrails)
verdict 승급(주의/영향→caution) · 출처 자동보정 · 위험표현 치환 · 종합 verdict 결정
⚙️ 키워드 기반 RAG입니다 (벡터 임베딩·pgvector 미사용). 성분명·음식명을 SQL ILIKE로 매칭합니다.

4개발 일정

기능 단계별 진행 (날짜는 작업 흐름 기준 · 필요 시 수정)

Phase 1

e약은요 API 통합 · 약 필터

식약처 e약은요(병용금기·주의)를 RAG 컨텍스트로 추가. 결과 화면에 "이번 검색 약만 / 내 약 모두" 필터 도입.

lib/easyDrug.tsapp/result/page.tsx
Phase 2

검색 우선순위 재설계

약 이름 검색 실패 문제 해결 — 한글→영문 성분 매핑(DRUG_KOR_TO_ENG)을 35→185개로 확장, 프롬프트 우선순위 재정렬.

lib/mfds.tslib/safety-llm.ts
Phase 3

가짜 매칭 제거 · 환각 방지

미등록 약에 다른 약 데이터를 반환하던 fallback 제거(0건은 정직하게 0건). LLM 환각 방지 규칙 추가.

lib/mfds.tslib/safety-llm.ts
Phase 4

동적 성분 해석 (제품허가 API)

하드코딩 한계 극복 — 매핑에 없는 약을 식약처 제품허가 API로 실시간 성분 조회. 미승인 시 자동 회로차단.

lib/ingredient.tslib/mfds.ts
Phase 5

약 관리 개편 (촬영일 · 그룹)

촬영 날짜 기록 + 함께 촬영된 약을 묶음으로 관리. 기존 평면 데이터 자동 마이그레이션(하위 호환).

lib/storage.tsapp/my-meds/page.tsx
Phase 6

정보 패널 보강 · UI 복구

ℹ️ 정보 패널이 제품허가 API도 사용하도록 보강(암로디핀·와파린도 표시). 빌드/dev 캐시 충돌 복구.

app/api/easy-drug/route.tscomponents/DrugCard.tsx
Phase 7

로그인 게이트

약 인식까지는 비로그인 허용, 검증 결과는 로그인 필수. OAuth 왕복 후 입력 유지하여 결과 복귀.

app/food/page.tsxapp/result/page.tsx

7중요한 코드

프로젝트의 핵심을 이루는 5개 코드 (복사 가능)

① 동적 성분 해석 — 하드코딩 없이 임의의 약 → 공식 영문 성분

② RAG 검색 키워드 확장 — 정적 매핑 → API 폴백

③ 환각 방지 프롬프트 — 데이터 없으면 추측 금지

④ 촬영 날짜 그룹 저장 — 함께 촬영된 약 묶음 관리

⑤ 로그인 게이트 — 검증 결과는 로그인 필수

8트러블슈팅 & 성과

개발 중 해결한 핵심 문제

🩺 환각(잘못된 약 정보) 제거

미등록 약에 다른 약의 음식 키워드 매칭을 반환하던 fallback 제거 + 프롬프트 강화.

전: "카데프엘릭서는 칼륨 보충제…"(허위) → 후: Digoxin(강심제) 정확 매칭

🔁 매핑 확장성 한계 해결

수작업 매핑(틀린 항목도 존재: 놀텍=ilaprazole)을 제품허가 API 동적 해석으로 대체.

전: 5만+ 약 수동 등록 불가 → 후: 임의 약 자동 성분 해석

ℹ️ 정보 패널 커버리지

e약은요 단독으론 암로디핀·와파린·노바스크조차 0건 → 제품허가 API 병합.

전: "정보 없음" → 후: 성분·분류·제조사 표시

🛠 dev 캐시 손상 복구

dev 서버 가동 중 build 실행으로 .next 손상 → 정리 후 재기동. 이후 tsc --noEmit로 검증.
