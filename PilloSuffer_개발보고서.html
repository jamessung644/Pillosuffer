1프로젝트 개요

복용 중인 약과 음식·영양제의 상호작용 위험을 촬영 한 번으로 확인하는 모바일 웹 서비스

사용자가 약봉투를 촬영하면 OCR로 약품을 인식하고, 함께 먹는 음식·영양제를 입력하면 공신력 있는 의약품 데이터(식약처·DrugBank)를 근거로 AI가 안전 / 주의 / 위험 3단계로 판정합니다. 모든 판정은 "데이터에 없으면 추측하지 않는다"는 원칙 위에서 동작합니다.

📷 약봉투 인식

Google Vision OCR로 약을 인식하고 개인정보(이름·주민번호·병원명)를 자동 마스킹

🔬 성분 기반 분석

약품명을 공식 영문 성분으로 변환 후 DrugBank·식약처 데이터와 교차 검색

🤖 AI 안전 판정

검색된 근거로 Gemini가 위험도 3단계와 사유·출처를 생성 (RAG)

5문제 해결 방법

데이터 확보 · 사용자 정보 저장 · 활용 기술 중심

A. 데이터 확보 방식

신뢰할 수 있는 의약품·식품 데이터를 공신력 있는 출처에서 확보하고, 약품명→성분 변환 문제를 단계적으로 해결했습니다.

  • DrugBank 6.0Supabase 적재 · 2,512건
    공개 상호작용 데이터셋을 PostgreSQL 테이블에 적재해 자체 DB로 빠르게 조회 (영문 성분·상호작용 설명).
  • 식약처 e약은요DrbEasyDrugInfoService
    공공데이터포털 활용신청 후 실시간 호출. 효능·병용금기·주의·부작용(일반인용 쉬운 설명).
  • 식약처 제품허가DrugPrdtPrmsnInfoService07
    추가 활용신청. 약품명→공식 영문 성분·분류·제조사. 하드코딩 매핑의 한계를 극복한 핵심.
  • 가공식품·영양제Supabase 테이블
    식품·영양제 테이블로 검색 자동완성 제공.
  • 이미지 → 텍스트Vision · Gemini
    약봉투는 Google Vision OCR, 음식 사진은 Gemini 멀티모달로 품목명 추출.

핵심 해결: 약 이름으로 검색이 안 되던 문제 → 한글→영문 성분 정적 매핑(185개) + 매핑에 없으면 제품허가 API로 실시간 해석하는 2단계 구조로 해결. LLM 성분 추측은 오답 위험(예: 카데프엘릭서를 "dextromethorphan"으로 오인) 때문에 의도적으로 배제하고 공식 데이터만 사용.

B. 사용자 정보 저장 방법

민감한 복약 정보를 서버에 모으지 않는 프라이버시 우선(local-first) 설계를 택했습니다.

  • 복약 데이터localStorage: medGroups
    촬영 세션 단위 묶음(촬영 날짜 포함)을 사용자 기기에만 저장. 서버 미보관.
  • 하위 호환 미러localStorage: savedMedications
    평면 목록 자동 동기화로 기존 화면과 호환 + 무중단 마이그레이션.
  • 분석 임시 세션sessionStorage: scanSession·foodList
    탭 단위 임시 보관. 로그인(OAuth) 왕복 후에도 유지되어 결과로 복귀.
  • 프로필·히스토리localStorage
    프로필·최근 분석 기록(최대 10건)을 기기에 저장.
  • 로그인 인증Supabase Auth + Google OAuth
    비밀번호를 직접 받지 않고 OAuth에 위임. 세션은 보안 쿠키, 미들웨어가 자동 갱신.
  • 개인정보 보호PII 마스킹
    OCR 텍스트의 이름·주민번호·병원명을 LLM 전송 전 제거. 약품명만 분석에 사용.
C. 활용 기술
  • RAG
    외부 데이터 검색 → 컨텍스트 증강 → LLM 생성. 프레임워크 없이 직접 구현(키워드 매칭).
  • OCR · 멀티모달
    Vision OCR(약봉투) + Gemini Vision(음식 사진)으로 이미지를 구조화된 텍스트로.
  • 프롬프트 엔지니어링
    출처 우선순위·환각 방지·의료법 회피 표현을 규칙화해 답변 신뢰성·안전성 확보.
  • 회로차단 · 캐싱
    외부 API 실패 시 자동 비활성(가짜 데이터 차단) + 1주 캐시로 안정성·속도 확보.
  • 데이터 마이그레이션
    평면 저장 → 그룹 저장으로 전환하며 기존 사용자 데이터 무손실 자동 변환.

정확도 검증 — 약학정보원 기준 평가

현업 약사가 환자에게 음식–약물 상호작용을 안내할 때 가장 널리 쓰는 약학정보원(KPIC) 데이터를 정답(ground truth)으로 가정하고 PilloSuffer의 판정 결과를 대조했습니다. 약학정보원은 자체 구축한 데이터를 사용하며 외부에는 공개되지 않지만, 실제 임상 복약지도에서 사실상 표준 레퍼런스로 통용됩니다.

검증 결과
  • 일치도vs 약학정보원
    약학정보원이 보유한 항목에서는 PilloSuffer의 판정이 일관되게 일치했습니다.
  • 초과 커버리지app > KPIC
    약학정보원에는 수록되지 않은 상호작용까지 앱이 제시하는 사례가 확인됐습니다 — 오류가 아니라 보유 정보량의 우위입니다.
  • 원인why
    약학정보원은 비공개 내부 DB에 의존하는 반면, PilloSuffer는 DrugBank 6.0 정제 데이터와 대규모 문헌 텍스트마이닝 데이터를 함께 근거로 사용합니다.
📊 현업에서 실제로 사용하는 레퍼런스보다 PilloSuffer가 보유한 근거 데이터의 양이 훨씬 많았습니다. 약학정보원에서 "정보 없음"으로 끝나는 약·음식 조합에 대해서도, PilloSuffer는 공신력 있는 근거를 제시할 수 있었습니다.
